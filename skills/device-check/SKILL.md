# device-check — 實機走查

交付資料夾、規格來源見 `~/.claude/skills/my-flow/conventions.md`。操作手機照 mobile-mcp 的工具說明，以及專案層 CLAUDE.md 或 memory 裡的手機規則。

參數：組號或情境名稱 → 只走這些；沒帶 → 走全部情境。

## 步驟

1. **列情境**：每條寫操作步驟、預期結果、對照畫面來源（Figma 節點、PM 圖、設計稿截圖）。對照來源依專案 CLAUDE.md 的設計稿規則找；Figma 的記下畫面名稱與節點 ID；找不到的標「無對照」。完成條件：每條都有預期結果，對照來源有或明確標無。
2. **先問使用者**：用哪台手機、裝哪個 build、要不要清 App 資料或切輸入法。拿到同意才動手機。手機是共用的：動手前先看前景 App，不是這次要測的 App 時，用 ListAgents 看有沒有其他 session 正在忙，有就先告訴使用者、等使用者決定。
3. **準備**：安裝 build；記下要還原的狀態（輸入法、App 資料、登入狀態）。
4. **逐條走**：用元素清單判斷畫面。每條在關鍵畫面存截圖到 `device/<編號>.png`，對照畫面存到 `target/<編號>.png`（Figma 用 figma-bridge 的 `save_screenshots`）。結果記通過、失敗或無法驗（附原因）。
5. **比畫面**：每對實機與對照畫面列出看得到的差異：文案、元件、狀態、排版。只列差異，要不要改留給使用者。
6. **對數值**：對照來源是 Figma 節點的畫面，用 figma-bridge `get_node` 讀這次改到或新做的元件：文字的字級、字重、顏色，元件的尺寸、間距、圓角、背景色；圖片與插圖另外對透明度、混合模式（`blendMode`）、陰影等效果，以及匯出檔有沒有被畫框裁切（單獨匯出的圖不含混合效果，被裁掉的部分也不會出現）。在 code 找出同一個元件實際用的值（theme token 或直接寫的數值），逐項比對；Figma 的 px 對 dp／sp。對不上的列進「數值差異」，附 Figma 值、code 值與檔案:行號；code 用 token 時寫 token 名和它的實際值。code 直接寫數值、而專案有對應的 token 時（例如寫死 `16.sp`、專案有同值的字級 token），值對得上也列進數值差異，code 欄寫「寫死」並附建議的 token。對照來源不是 Figma 的畫面標「無數值來源」。這一步比的是 code，不從截圖量像素。完成條件：每個有 Figma 節點的畫面都對過，或寫明讀不到的原因（例如節點是圖片）。
7. **還原手機**，回報還原了哪些。
8. **寫 `device-check.md`**，在檢查紀錄加一列。「花多久」用第一張與最後一張截圖的檔案時間（或指令輸出的時間）算，統計欄從上面的明細重數，不憑印象填；沒有時間來源就寫「沒記」。

完成條件：每條情境都有結果和截圖路徑；失敗或無法驗的都有原因；有 Figma 節點的畫面都對過數值；手機已還原。

## `device-check.md` 格式

```
產生：<時間> @ <commit>（未提交改動：有／無）

| # | 情境 | 結果 | 實機 | 對照 | 差異 |
|---|---|---|---|---|---|

## 失敗與無法驗
<每條：怎麼重現、看到什麼、預期什麼>

## 數值差異
| # | 畫面（節點 ID） | 元件 | 項目 | Figma | code | 位置 |
|---|---|---|---|---|---|---|

## 檢查紀錄
| 日期 | 範圍 | 花多久 | 失敗 | 畫面差異 | 數值差異 |
|---|---|---|---|---|---|
```
