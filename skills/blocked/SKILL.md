# blocked — 還卡著什麼

只讀，不改任何檔案。

## Step 0 — 找出這個專案有哪些「卡住」的來源

| 來源 | 怎麼認 | 找什麼 |
|---|---|---|
| feature-doc | 有 `.claude/docs/*.md` | ① 含 `⏸️`、`⏸`、`blocked` 的行；排除引用行（`>` 開頭，多半是圖例）與變更紀錄（「狀態由…改為」）。② **「待辦／跟外部對齊」表的每一列**，不論有沒有 `⏸️`：這張表的列多半不帶 `⏸️`，只抓 ① 會漏掉；每列的「移除條件」欄是等外部項目的移除條件出處。③ 註明「延後：<原因>；再問：<條件>」的題（`/my-flow` 規定記在待辦表）。專案有 `blocked-check.sh --manual` 這類腳本時，先跑它，再補 ②③ |
| code 標記 | 專案 CLAUDE.md 或 memory **有宣告**的標記寫法（例：`TODO(等後端)`、`TODO: API not yet available`、`🚧`） | 用宣告的寫法搜 code。沒有宣告就不搜一般的 TODO（雜訊太多），改問使用者要不要納入 |
| 個人追蹤清單 | memory 或 CLAUDE.md 提到的清單檔（例：repo 外的 `待後端事項.md`） | 每一筆的內容與「收掉條件」 |

## Step 1 — 每個項目是真的還卡著嗎

feature-doc 的 ⏸️ 項目依卡住的原因分類：

- **卡在其他 Slice** → 查那些 Slice 的狀態
  - 全都 ✅ → 🟢 **其實已經可以做**
  - 還有沒完成的 → ⏸️ 卡在其他任務
- **描述外部依賴**（後端 API、設計稿、PM 決定）→ ⏳ 等外部
- **Scenario 未定義**（`⏸️ blocked: Scenario 未定義`）→ 🕓 列在「延後再問」，等使用者補完 GIVEN/WHEN/THEN

feature-doc 待辦表的列：「屬於誰」欄是後端／PM／QA → ⏳ 等外部；是使用者 → 🕓 延後再問；是 App → ➖ 沒被擋、只是還沒做（「要不要現在做」由 `/my-flow` 提醒）。註明「延後」的題另列，附原因與再問條件。

⏸️ Slice 的移除條件取自待辦表對應的列，對不到就標「⚠️ 寫不清楚」。

移除條件要能直接驗。「等後端確認」不是移除條件，「`GET /media/{id}` 回傳含 `expiresAt`」才是；寫不清楚的標「⚠️ 寫不清楚」。

延後記的是「**當時**決定先不處理」，證明的是當時有人知道，不是現在還成立。

## Step 2 — 對帳：code 標記 ↔ 追蹤清單

專案有宣告的 code 標記時，跟追蹤清單、feature-doc 待辦表比對：
- code 有標記、清單沒有這筆 → 清單漏記
- 清單有這筆、code 已經找不到標記 → 可能已經收掉、清單該更新，或是標記被誤刪
- 標記的移除條件跟 feature-doc 待辦表的「移除條件」欄寫的不一樣 → 列出兩邊原文

只列出來，不自己改。

## Step 3 — 輸出

```markdown
## Blocked 清單（{日期}，{專案}）

### 🟢 其實已經可以做（卡的條件已解除）
- {文件} {Slice 或項目}：原本卡在 {Slice}，已完成

### ⏳ 等外部
- {文件} {項目}：{在等什麼}（移除條件：{…或「⚠️ 寫不清楚」}）
- {檔案:行} {code 標記內容}（移除條件：{標記自帶的，或清單的收掉條件}）

### ⏸️ 卡在其他任務
- {文件} {項目}：等 {Slice}（未完成）

### 🕓 延後再問
- {文件} {題名}：延後原因 {…}；再問條件 {…}

### 📝 清單與 code 對不上
- {哪一筆、哪一邊缺}

### ➖ 沒被擋、只是還沒做
- {文件}：{N} 項
```

移除條件相同的項目是同一件事，合併成一條，列出它出現的每個位置。

完全沒有卡住的事項時，只印一行：「✅ 目前沒有 blocked 事項」。

## 注意

- **只讀**：不改狀態、不刪標記，那是使用者的事
- 清單的收掉條件寫得能直接驗時（例：「swagger 的某 API 出現某欄位」），可以**提議**現在去驗，得到同意才驗；這個 skill 本身只列不驗
