# 案例：DayRouteMap

用我的個人專案 [TravelRecordList](https://github.com/ppking2897/TravelRecordList)（Kotlin Multiplatform 旅遊行程 App）裡的一個功能，說明這套流程實際怎麼運作。

以下內容都來自該專案的[規格文件](https://github.com/ppking2897/TravelRecordList/blob/master/.claude/docs/DayRouteMap.md)和 Git 紀錄。審查與實機的完整報告放在 repo 外，沒有公開，所以這裡只引用規格文件留下的摘要。

這個功能完成於 2026-11-04，當時的流程比這個 repo 的版本早，例如「確認文件列的測試真的存在」是之後才加的。

## 功能

旅途中想知道「今天怎麼走」「下一站怎麼去」。路線頁可以一鍵把當天的地點交給 Google 地圖，也能查相鄰兩站的大眾運輸。

同一個功能也處理了一個舊問題：原本的地圖頁和路線頁功能重疊，所以把地圖頁拿掉。

## 1. 規劃：先試做，發現方向不對就改

一開始試做 App 內地圖加 Routes API，但 Routes API 在日本查不到大眾運輸。於是放棄，改成用網址跳到 Google 地圖 App，也因此不需要呼叫付費 API。

規格最後整理成：

| 項目 | 數量 |
|---|---|
| Requirement（系統承諾） | 4 條 |
| Scenario（具體情境） | 13 條 |
| Slice（可獨立交付的分組） | 3 組 |

風險分級也寫在規格裡，理由要講得出來：

| Slice | 高風險 | 理由 |
|---|---|---|
| 1 當天路線與怎麼去 | 否 | 只開外部網址，不換 App 內的頁面，不改存起來的資料 |
| 2 從目前位置過去 | 否 | 只開外部網址 |
| 3 拿掉地圖頁 | **是** | 地圖圖示的目的地改變，還拿掉一個 route |

## 2. 實作與測試：證明測試會紅

組網址的規則寫成純函式（`RouteGoogleMapsLink.kt`），每條邏輯情境都對應到具體的測試，再故意把程式改壞，確認測試會紅。

| 情境 | 故意改壞的方式 | 結果 |
|---|---|---|
| 兩站以上的天可以開多站路線 | 漏掉中途站、指定大眾運輸、不照清單順序、不做編碼 | 都紅 |
| 超過 11 站只帶前 11 站 | 不截斷、11 站也標成截斷 | 都紅 |
| 從目前位置到這一站 | 帶了起點、沒指定大眾運輸 | 都紅 |

也反過來做了一次：把網址參數的順序對調，這不違反需求，測試維持綠，證明測試沒有綁死實作細節。

## 3. 單元測試驗不到的，就老實寫出來

規格文件直接記下測試的邊界。例如「按地圖圖示進入路線頁」這條：

> 單元測試只驗 ViewModel 那段；圖示接到 `GenerateRoute`、`App.kt` 推路線頁這段接線沒有單元測試，靠實機。

高風險的 Slice 3 走了實機。除了正常路徑，也驗了這些容易出事的情況：

- 左上角箭頭和系統返回，都回到同一個行程的詳情
- 快速連點地圖圖示後，按一次返回就回到詳情
- 舊版停在地圖頁時覆蓋安裝，App 不會閃退

## 4. 審查抓到的問題

審查後的修正集中在 commit `4c0c461`：

| 問題 | 修正 |
|---|---|
| 站名含 `\|` 時，Google 會把它當成兩站 | 把站名裡的 `\|` 換成空白 |
| 手機上沒有能開網址的 App 時會閃退 | 改成底部提示 |
| 連點地圖圖示會推兩層路線頁 | 頂端已是同一趟的路線頁就不再推 |
| 站的順序另外依 `order` 排序，跟畫面用的依據不同（現況結果相同） | 改照清單順序，跟畫面一致 |

另外也清掉了拿掉地圖頁後沒人使用的元件。前三項都是正常操作時碰不到，只有在特殊資料或操作下才會出事的問題。

## 5. 合併後核對

功能分支合進 `master` 後再核對一次規格（這是 `verify-feature` 的工作），規格文件最底留下核對標記：

```
**Verified**: 2026-11-04 @ b77bda3
```

這個標記的意思是「這份文件在這個版本跟程式核對過」，不是「文件寫完的時間」。

## 還沒做完的事

iOS 開啟 Google 地圖還沒驗證，因為需要 Mac。它留在待辦表，並寫明能直接驗證的移除條件，也在程式檔頭留了標記：

> 在 iOS 實機按「當天路線」「怎麼去」與每站的地圖按鈕，都能開啟 Google 地圖或瀏覽器並帶入各站，且確認瀏覽器時的站數上限與提示文字相符。

沒驗到的就寫沒驗到，這也是這套流程要求的一部分。
